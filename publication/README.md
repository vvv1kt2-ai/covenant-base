# Ковенанты облигаций — подготовка публикации

> **Где что лежит.** Этот каталог — публикационный слой проекта: скрипты в `tools/`,
> входные и выходные данные в `data/`, глоссарий в `CONTEXT.md`, решения в `docs/adr/`.
> Парсер эмиссионной документации — в корне репозитория, к этому слою он относится только
> как источник `new_issues_covenants.xlsx`.
>
> **Запуск.** По умолчанию скрипты работают с `publication/data/` и `publication/img/`
> этого репозитория — код и данные не расходятся, рабочая копия одна. Внешние источники
> задаются переменными окружения:
>
> | Переменная | По умолчанию | Назначение |
> | --- | --- | --- |
> | `COVENANT_WS` | `publication/data/` | каталог входных и выходных данных |
> | `COVENANT_MOEX` | `D:/API мосбиржи/data/` | кэши MOEX ISS |
> | `COVENANT_SCRAPE` | `D:/data-scraping/` | список непубликовавших отчётность |
> | `COVENANT_IMG_OUT` | `publication/img/` | растровые версии материала |
> | `COVENANT_OUT`, `COVENANT_OUT_MD` | `COVENANT_WS` | пути результата сборки |
>
> Запуск из корня репозитория: `python publication/tools/build_covenant_publication.py`.
> Промежуточные файлы пишутся в `COVENANT_WS/tmp/` и в git не попадают.
>
> Сборка воспроизводима по содержимому: проверено, что повторный запуск даёт ноль
> различий по ячейкам. При этом `xlsx` перегенерируется с новыми служебными метками,
> поэтому git может показать файл изменённым при неизменных данных — сверяйте значения,
> а не байты.

Проект собирает из трёх рабочих реестров (рейтинговые группы **B / BB / BBB**) и файла
новых выпусков один публикационный материал: **какие ковенанты дают владельцу право
предъявить облигации к досрочному погашению**. Дополнительно по каждому выпуску
определяется ПВО — представитель владельцев облигаций.

Результат — воспроизводимый набор файлов: сборка запускается скриптами из `tools/`,
исходные реестры не редактируются вручную, кроме случаев, зафиксированных в коде
(таблица `MANUAL`).

```
│   ├── ПВО_справочник.xlsx                 справочник ПВО
│   ├── Проверка_непубликовавших_ковенанты.xlsx, Непубликовавшие_ПВО.xlsx
│   ├── tmp/                                кэш и резервные копии (в git не попадает)
│   └── README.md                           перечень файлов — единственное, что в git
├── tools/                                  скрипты сборки (отслеживаются)
├── img/                                    растровые версии материала (в git не попадает)
├── docs/adr/                               архитектурные решения
├── CONTEXT.md                              глоссарий
└── README.md                               этот файл
```

Файлы данных в git не входят: реестры, выгрузки и готовый материал содержат информацию
по эмитентам, а репозиторий публичный. Перечень того, что должно лежать в `data/`,
и порядок восстановления — в `data/README.md`.

Вне репозитория остаются два файла рабочего каталога: `заметка.docx` — исходный текст
вводной части публикации (docx в git не хранится), и ярлык `marked — ярлык.lnk`,
указывающий на `D:\API мосбиржи\data\covenants\marked` — каталог с решениями о выпуске в PDF.

## Пайплайн

Порядок важен: справочник ПВО собирается до записи колонок в реестры, а публикация —
после, потому что берёт колонку `ПВО` уже из реестров.

```bash
# 1. ПВО: сбор решений о выпуске и разбор раздела 9
python tools/fetch_pvo.py [--limit N]     # → tmp/pvo_map.json, tmp/pvo_txt/, tmp/pvo_pdf/
python tools/resolve_pvo.py               # → tmp/pvo_final.json (канонизация, статусы, сайты)

# 2. Запись колонок «ПВО | Сайт ПВО | Статус ПВО» в 4 реестра + справочник
python tools/add_pvo_columns.py           # резервная копия → tmp/backup_pvo_<дата>/

# 3. Публикация: свёртка ковенант по выпуску, дедупликация групп, исключения
python tools/build_covenant_publication.py

# 4. Растровые версии материала
python tools/build_covenant_images.py

# 5. Проверка непубликовавших отчётность
python tools/check_missing_covenants.py   # → Проверка_непубликовавших_ковенанты.xlsx
python tools/build_missing_pvo.py         # → Непубликовавшие_ПВО.xlsx
```

Шаги 1–2 нужны только при обновлении данных ПВО; при изменении реестров достаточно
шагов 3–4.

### Скрипты

| Скрипт | Назначение |
|---|---|
| `fetch_pvo.py` | Собирает ISIN из 4 файлов, скачивает решения о выпуске с Финама, извлекает текст через `workbuddy-pdf`, парсит раздел «Сведения о представителе владельцев облигаций». Есть кэш — повторный запуск докачивает только пропуски |
| `resolve_pvo.py` | Канонизация названий (16 организаций), сопоставление со списком ЦБ, сайты, статусы |
| `add_pvo_columns.py` | Дописывает три колонки в реестры, собирает `ПВО_справочник.xlsx`, делает резервную копию |
| `build_covenant_publication.py` | Основная сборка: таксономия, свёртка, дедупликация, исключения, xlsx + md |
| `build_covenant_images.py` | HTML → headless Chrome → PNG (×2), обрезка фона, сборка общего PDF |
| `check_missing_covenants.py` | Сопоставление списка непубликовавших с реестрами по ИНН |
| `build_missing_pvo.py` | Таблица «Компания — ПВО» для непубликовавших |

## Правила обработки

Зафиксированы в `docs/adr/0001-taksonomiya-kovenant-i-deduplikaciya.md`:

1. **Шесть канонических категорий** вместо 30 исходных наименований:
   `Отчётность · Финковенант · Кросс-дефолт · Делистинг · Смена контроля · Иное`.
   Отчётность эмитента / группы / поручителя схлопнута в одну категорию.
2. **Составные категории** (`Категория⏎+ триггер`) раскрываются по объединению
   оснований, а не только по базовой части.
3. **Одна строка = эмитент + уникальный набор ковенант + перечень выпусков.**
4. **Дубль ISIN** показывается один раз — в группе с более низким рейтингом.
5. **«Иное» переклассифицируется по цитате** (`RECLASS_BY_TEXT`); записи, где
   формулировка не содержит конкретного события, исключаются.
6. **Ручная проверка** фиксируется в таблице `MANUAL` скрипта (ISIN → категории или
   причина исключения) и имеет приоритет над автоматическим разбором, но не отменяет
   исключение по сроку погашения.

Основания исключения: нет права требования досрочного погашения; погашение до
31.12.2026; скан без текстового слоя; неопределённая формулировка; эмитент в дефолте.

## Ограничения

- Точность переклассификации «Иное» зависит от полноты цитат в исходных реестрах;
  при их изменении `RECLASS_BY_TEXT` нужно перепроверять.
- Сопоставление эмитентов по названию — резервный путь. Суффиксы `ЛК` и `ПКО` значимы:
  без них «ЛК Прогресс» ошибочно совпадает с ЗАО «ПРОГРЕСС». Первичный ключ — ИНН.
- `volsta.ru/issuers` — список размещений клиентов, а не ПВО; источник ПВО — только
  решение о выпуске, список Волсты используется для сверки.
- У ряда выпусков в реестрах имя эмитента стоит лишь в первой строке блока; в BBB
  колонка «Эмитент» содержит имя выпуска, имя эмитента подтягивается из MOEX ISS.
- `Ковенанты_для_публикации_обновлено.*` — предыдущий снимок без колонки ПВО,
  оставлен для сравнения; актуальны файлы без суффикса.
- `tmp/` содержит кэш PDF/текстов и резервные копии реестров; в публикацию не входит.
