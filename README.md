# Парсер ковенантов облигаций (bonds.finam.ru)

Автоматический парсинг раздела **5.6.1 «Досрочное погашение облигаций по требованию владельцев»** из эмиссионных документов российских облигаций, размещённых на [bonds.finam.ru](https://bonds.finam.ru/).

## Архитектура

`
ISIN-список → bonds.finam.ru (Playwright) → PDF-документ → pdfplumber → JSON → Excel
`

| Этап | Технология | Описание |
|------|-----------|----------|
| Поиск карточки | Playwright | Обход ServicePipe anti-bot, поиск по ISIN |
| Скачивание PDF | httpx | Статический хостинг st.finam.ru (без антибота) |
| Извлечение текста | pdfplumber | Парсинг раздела 5.6.1, 4 паттерна событий |
| Экспорт | openpyxl | JSON → Excel с жёлтой подсветкой ошибок |

## Быстрый старт

### Зависимости

`ash
pip install playwright httpx beautifulsoup4 lxml pdfplumber openpyxl
playwright install chromium
`

Или установить из equirements.txt в существующее окружение:

`ash
pip install -r requirements.txt
`

### Запуск

`ash
# Все ISIN из CSV-файла
python parser.py --input BBB.csv

# Один ISIN
python parser.py --isin RU000A105TG7

# С лимитом (первые N штук)
python parser.py --input BBB.csv --limit 10

# Дозагрузка: пропустить уже обработанные
python parser.py --input BBB.csv --resume

# Повторить только ошибочные ISIN
python parser.py --input BBB.csv --retry-errors

# Видимый браузер (для отладки)
python parser.py --input BBB.csv --no-headless
`

### Экспорт в Excel

`ash
python export_excel.py          # results.json → covarianants.xlsx
python export_excel.py -i data.json -o output.xlsx
`

### Переобработка из кеша (без обращения к сайту)

`ash
python reparse_missing.py       # Перепарсит все ISIN из скачанных PDF
`

| Эмитент | Выпуск | ISIN | Рейтинг | Ковенантов | № | Категория | Суть | Документ | Пункт | Стр. | Файл | Цитата | Источник |
|---------|--------|------|----------|------------|---|-----------|------|----------|-------|------|------|--------|----------|

- **Жёлтая подсветка** + красный текст «⚠ ОШИБКА ПАРСИНГА» — ISIN с ошибками (сканы, ZIP,битые PDF), требующие ручной проверки.

## Логика парсинга раздела 5.6.1

### 1. Проверка наличия

Первые 5 текстовых строк раздела проверяются на ключевые фразы:
- не предусмотрена/о/ы
- не установлена/о/ы
- не предоставлена/о/ы

Если найдено → **0 ковенантов**.

### 2. Извлечение событий (4 паттерна, приоритетный порядок)

| # | Паттерн | Описание |
|---|---------|----------|
| 1 | Событие досрочного погашения ... – N: | Формулировка вида «Событие досрочного погашения ... – 1:» |
| 2 | Событие N: в начале строки | Только именительный падеж + двоеточие |
| 3 | Список N) ... или N). ... | Нумерованный список, ≥50% ключевых слов совпадают |
| 4 | Буллеты ✓/-/–/—/•/◆/▪/• | ≥2 элемента в списке |

### 3. Фильтр

- **Фильтр дат**: пропускает предложения вида «является/считается/наступает/возникает» в начале
- **Дедупликация**: по номеру события
- **Фоллбек**: если is_provided=True, но события не найдены → создаётся 1 ковенант из текста раздела

### 4. Исключения

- **Федеральные законы** — не считаются ковенантами
- **Ссылки на программу** — пропускаются (парсинг программ не реализован)

## Защита от блокировок

- Задержка **3–8 сек** между запросами
- Автопауза **5 мин** после 3 последовательных ошибок
- Перезапуск браузера при сбоях
- Обход ServicePipe JS-челленджа через Playwright
