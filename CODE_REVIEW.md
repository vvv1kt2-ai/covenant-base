# Обзор кода: Парсер ковенантов облигаций

Пайплайн: bonds.finam.ru (Playwright) → st.finam.ru (PDF) → pdfplumber → JSON → Excel
192 ISIN из BBB.csv, 127 ковенантов, 69 эмитентов с ковенантами

---

## КРИТИЧНО

### 1. Неверный ISIN при нескольких результатах поиска

**Файл:** `finam_client.py`, метод `_extract_hex_code_from_results()`

При поиске ISIN на bonds.finam.ru могут вернуться несколько результатов. Если ни один из них не совпадает с искомым ISIN (например, из-за разницы регистра или формата), код возвращает hex-код первого попавшегося результата. Это означает, что для ISIN `A` можно получить карточку ISIN `B` — и парсинг будет работать с чужими данными.

Текущая логика (примерно строка 237):
```
# If no exact ISIN match, return the first details link
```

**Исправление:** Если точное совпадение не найдено — возвращать `None` и логировать предупреждение. Не полагаться на первый попавшийся результат.

### 2. Тройное дублирование кода построения covenant

**Файлы:** `parser.py` (строки 207 и 221), `reparse_missing.py` (строки 45 и 60)

Словарь `covenant` с 9 ключами скопирован в 3 места:
- `parser.py` → ветка `if clause.events` (события)
- `parser.py` → ветка `else` (без событий)
- `reparse_missing.py` → обе ветки

При добавлении нового ключа в covenant придётся менять все 4 места. Любое расхождение между ними приведёт к рассинхронизации JSON.

**Исправление:** Вынести в отдельную функцию `_build_covenant(clause, event=None, seq_number=1)` в общем модуле (например, `models.py`). Использовать её во всех трёх местах.

### 3. Некорректный сброс счётчика ошибок после cooldown

**Файл:** `finam_client.py`, метод `_check_block()` (строка 94)

После паузы в `block_cooldown_seconds` код делает:
```python
self._consecutive_errors = max(0, self._consecutive_errors - 1)
```

Это уменьшает счётчик на 1 вместо сброса в 0. Если ошибка повторится сразу после cooldown, счётчик станет 2 вместо 1 — и при следующей ошибке (уже 3-й подряд после cooldown) снова будет cooldown вместо нормальной работы.

При этом в `_handle_block()` (строка 109) счётчик корректно сбрасывается в 0: `self._consecutive_errors = 0`.

**Исправление:** Заменить `max(0, self._consecutive_errors - 1)` на `self._consecutive_errors = 0`.

## ВАЖНО

### 4. Поздний импорт httpx

**Файл:** `finam_client.py`, метод `download_file()` (строка 439)

`import httpx` находится внутри метода, а не в начале файла. Если httpx не установлен, ошибка проявится только при вызове `download_file()`, а не при старте программы. При этом остальной пайплайн (парсинг, поиск) может отработать успешно — и только на этапе скачивания PDF выяснится, что зависимость не установлена.

**Исправление:** Перенести `import httpx` на уровень модуля, рядом с `from playwright.sync_api import ...`. Проверку наличия можно сделать в `__init__` класса `FinamClient`.

### 5. Повторное объявление `_DATE_DEF_WORDS`

**Файл:** `pdf_parser.py`, метод `_extract_events()` (строки 223 и 259)

Переменная `_DATE_DEF_WORDS` объявлена дважды в пределах одного метода — один раз перед Pattern 1, второй раз перед Pattern 2. Значения идентичны. Второе объявление перезаписывает первое, хотя на текущий результат это не влияет (значения одинаковые). При чтении кода создаётся впечатление, что переменные разные.

**Исправление:** Объявить `_DATE_DEF_WORDS` один раз — в начале метода `_extract_events()` или как атрибут класса/константу модуля.

### 6. Флаг `--retry-errors` требует `--input`

**Файл:** `parser.py`, строка 277

При вызове `python parser.py --retry-errors` без `--input` или `--isin` будет ошибка: `Either --input or --isin is required`. Но логика `--retry_errors` (строка 315) загружает ISINs из `results.json` и фильтрует по ошибкам — ей не нужен входной файл.

**Исправление:** При `--retry_errors` пропускать проверку `if not args.input and not args.isin`, или автоматически загружать ISINs из `results.json`.

### 7. Поле `total_covenants` в JSON не используется

**Файл:** `export_excel.py`

Экспорт берёт количество ковенантов из `len(covenants)`, а не из поля `total_covenants` в JSON. Если `total_covenants` рассинхронизируется с реальным списком (например, при ручном редактировании JSON), данные в Excel будут некорректными. Само поле `total_covenants` в `export_excel.py` фактически не используется — оно только в `results.json`.

**Исправление:** Либо убрать поле `total_covenants` из JSON (считать длину списка), либо использовать его в экспорте вместо `len(covenants)`. Выбрать одно.

## МЕЛОЧЬ

### 8. Нарушение единообразия именования

**Файл:** `config.py`

Поле `finam_card_urlTemplate` написано в camelCase, все остальные поля — в snake_case. Для dataclass-а в Python стандарт — snake_case.

**Исправление:** Переименовать в `finam_card_url_template`.

### 9. Работа с относительными путями в reparse_missing.py

**Файл:** `reparse_missing.py`

Скрипт использует `Path("downloads")` — относительный путь. Если запускать из другой директории, файлы не будут найдены. В `parser.py` и `finam_client.py` используется `config.downloads_dir`, который строится от `__file__`.

**Исправление:** Использовать `Config().downloads_dir` вместо `Path("downloads")`.

### 10. Потенциальная обрезка текста в `_clean_event_text()`

**Файл:** `pdf_parser.py`

Regex `считается\s+наступившим.*$` удаляет всё от "считается наступившим" до конца строки. Если после этого фраза идёт полезный текст (например, условие наступления события), он будет обрезан.

**Исправление:** Ограничить удаление — например, удалять только до следующего предложения или до конца абзаца, а не до конца всего текста.

### 11. Magic numbers в `_wait_for_servicepipe()`

**Файл:** `finam_client.py`

`time.sleep(3)` и `time.sleep(1)` используются без пояснения. Непонятно, почему именно эти значения, и сложно подбирать при изменении условий.

**Исправление:** Вынести в константы с осмысленными именами (например, `SERVICEPIPE_POLL_INTERVAL = 3`, `SERVICEPIPE_POST_LOAD_WAIT = 1`).

### 12. Глобальные вызовы logging в parser.py

**Файл:** `parser.py`, функции `load_isin_list()` (строка 72) и `save_results()` (строка 253)

Используется `logging.info()` вместо `logger = logging.getLogger(__name__)`. В скрипте это не критично, но при импорте модуля из другого кода логи пойдут в корневой logger без префикса имени модуля.

**Исправление:** Заменить на `logger = logging.getLogger(__name__)` и использовать `logger.info()`.

### 13. Нет обработки ошибок в reparse_missing.py

**Файл:** `reparse_missing.py`

Если парсинг одного ISIN упадёт с необработанным исключением, весь скрипт остановится. В `parser.py` аналогичная логика обёрнута в `try/except` с логированием.

**Исправление:** Обернуть тело цикла `for r in data:` в `try/except` с логированием ошибки и продолжением цикла.

### 14. Отсутствие context manager для workbook

**Файл:** `export_excel.py`

`Workbook()` создаётся без `try/finally`. Если ошибка произойдёт до `wb.save()`, объект останется в памяти. Маловероятно, но не соответствует best practice.

**Исправление:** Обернуть в `try/finally` с вызовом `wb.close()` в блоке `finally`.
